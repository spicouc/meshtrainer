FLUXOS CLAU
===========

1. CREAR + VALIDAR JOB
   UI/CLI -> API POST /api/jobs -> MeshTrainerService
     -> valida backend (registry lazy), model (snapshot), dataset (JSONL)
     -> status DRAFT -> VALIDATING -> READY | FAILED(errors)

2. START JOB (només si validation == PASS)
   API POST /api/jobs/{id}/start -> JobRunner (procés separat)
     a. prepare: 1 càrrega backend (seed fixa)
        -> adapter_0 autoritatiu + base_model_hash + ETTs per shard
        -> close/del/gc/malloc_trim  (RSS 4GB -> 390MB, lliçó R1.2)
     b. round.create (ADMIN) -> assignment.create (ADMIN)
     c. spawn worker A (real) -> [stagger LOAD] -> spawn worker B (real)
        (PID A != PID B; mateix base_model_hash; shards/leases diferents)
     d. workers: register -> calibrate -> lease -> step -> commit
        -> checkpoint -> contribution.register
     e. ADMIN: contribution.validate -> contribution.activate (quòrum)
     f. round.fedavg -> adapter del round -> següent round
     g. complete: adapter final + metrics JSON + manifest + summary

3. MONITOR (SSE)
   GET /api/jobs/{id}/events -> events reals del core:
   round.create, assignment.create, worker.lease, contribution.submit,
   contribution.validate, contribution.activate, round.fedavg,
   recovery.event, job.complete/failed/cancelled

4. CANCEL (mai kill -9 immediat)
   RUNNING -> CANCELLING
     -> SIGTERM cooperatiu als workers
     -> expirar/invalidar leases (LeaseManager existent)
     -> cap nova assignment; contribucions en vol no s'activen
     -> persistir estat -> esperar sortida neta (timeout)
     -> SIGKILL només com a últim recurs (registrat) -> CANCELLED

5. ARTEFACTES
   GET /api/jobs/{id}/artifacts -> adapter final + intermedis + metrics
   + config + manifest + summary; sha256 verificable per artefacte
